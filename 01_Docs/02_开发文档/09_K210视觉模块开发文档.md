# K210 视觉模块开发文档（Maix Bit + ATK-OV2640）

> 项目：XY_Vision_Picker（STM32F407 两轴视觉抓取）
> 日期：2026-10-10　状态：代码已交付，待硬件联调

## 一、结论摘要

1. **K210 与 OV2640 兼容**（MaixPy 固件原生支持），但**接口形式存在硬约束**：
   - OV2640 的 **D0~D7 数据线是 K210 芯片专用引脚**（BGA M 行球位，K210 数据手册引脚图确认），**只从 Maix Bit 的 24P FPC 摄像头座引出，排针上没有**，无法杜邦飞线。
   - 控制线（SCCB/RST/VSYNC/PWDN/HREF/XCLK/PCLK）在 MaixPy 固件中**默认映射 IO40~IO47**（Maix Bit 引脚表确认，4.7K 上拉，1.8V），且可通过 fpioa_manager 重映射到任意 IO。
   - 因此 ATK-OV2640 红版（2×9=18pin 排针）接入 Maix Bit **必须经 24P FPC 转接**（转接板或直接换带 FPC 排线的 OV2640 模块）。
2. **历史核查表的修正**：此前"SDA→IO9、SCL→IO10、RST→IO11、VSYNC→IO12、PWDN→IO13、XCLK→IO14、PCLK→IO15、HREF→IO17"的飞线方案**仅对控制线成立且需代码重映射**；数据线 D0~D7 无排针可用。**推荐放弃飞线，全部走 FPC 座默认引脚（代码零配置）**。
3. **UART 通道**：K210 用 UART1（IO6=TX / IO7=RX）。IO4/IO5 是 UARTHS（板载 CH552 USB 串口桥，IDE/REPL 用）不可占用。
4. **固件协议对齐**：K210 输出 `$cx,cy,flag\n`（115200-8-N-1），STM32 `comm_uart.c` 以 `sscanf("$%d,%d,%d")` 解析，flag=1 有效。

## 二、引脚核查过程（可复现）

| 来源 | 结论 |
| --- | --- |
| K210 数据手册（kendryte_datasheet_20180822152307.pdf）引脚矩阵 | DVP_D0~D7 = BGA M 行 L4~L12 专用球位，不在 IO0~47 体系 |
| Maix Bit V2.0 Datasheet 引脚分配表 | IO40=DVP_SDA、IO41=DVP_SCL、IO42=DVP_RST、IO43=DVP_VSYNC、IO44=DVP_PWDN、IO45=DVP_HSYNC、IO46=DVP_XCLK、IO47=DVP_PCLK（4.7K 上拉，1.8V） |
| MaixPy fpioa_manager 文档 | sensor 模块默认注册 PIN40~PIN47 为上述 CMOS 功能，与 Maix Bit 硬件一致 |
| Maix Bit Datasheet V2.0 | 摄像头座 = 24P 0.5mm FPC（OV2640/OV7740/OV5640） |
| ATK-OV2640 红版 V1.2 实物核查（历史） | 2×9=18pin 排针接口，需转接 |

## 三、硬件接线方案

### 方案 A（推荐）：FPC 直连，代码零引脚配置

ATK-OV2640 18pin 排针 → **24P FPC 转 2.54mm 排针转接板**（或改用带 FPC 排线的 OV2640 模组）→ 插入 Maix Bit 24P 摄像头座。

| OV2640 信号 | Maix Bit 默认引脚 | 说明 |
| --- | --- | --- |
| D0~D7 | 24P FPC 座（芯片专用） | 不可重映射 |
| SDA | IO40 | 固件默认 |
| SCL | IO41 | 固件默认，4.7K 上拉 |
| RST | IO42 | 固件默认 |
| VSYNC | IO43 | 固件默认 |
| PWDN | IO44 | **必须接 GND/拉低**（否则模组待机） |
| HREF | IO45 | 固件默认 |
| XCLK | IO46 | 模组自带晶振可不接 |
| PCLK | IO47 | 固件默认 |
| VCC/GND | 3.3V/GND | — |

### 方案 B：控制线飞线到排针（仅当无 FPC 可用）

- 数据线 D0~D7 **必须仍走 FPC 座**；控制线可按历史表飞线 IO9~IO17，但需在代码中 `fm.register` 重映射（`main.py` 未内置，需要时自行添加），不推荐。

### 串口（K210 → STM32）

| K210 | 信号 | STM32 |
| --- | --- | --- |
| IO6 | UART1_TX | PB11 (USART3_RX) |
| IO7 | UART1_RX | PB10 (USART3_TX) 可选 |
| GND | 共地 | GND |

| `README.md` | 运行方式/接线/协议/联调/FAQ |

关键代码路径：

```python
fm.register(6, fm.fpioa.UART1_TX, force=True)   # IO6 -> UART1 TX
fm.register(7, fm.fpioa.UART1_RX, force=True)   # IO7 -> UART1 RX
uart = UART(UART.UART1, 115200, 8, None, 0)
sensor.reset(); sensor.set_pixformat(sensor.RGB565)
sensor.set_framesize(sensor.QVGA)               # 320x240
RED_THRESHOLD = (30, 100, 15, 127, -10, 127)    # LAB 红色（可标定）
# 每帧: find_blobs -> 最大色块 -> uart.write('$%d,%d,%d\n' % (cx, cy, flag))
```

## 六、联调步骤

1. MaixPy IDE 运行 `main.py` → 画面实时框出红色目标。
2. `calibrate.py` 标定 `RED_THRESHOLD`（目标放画面中心读 L/A/B）。
3. PC 串口助手接 IO6 → 确认 `$cx,cy,1` 帧格式。
4. K210 IO6 → STM32 PB11（共地）→ 观察 STM32 串口/CAN 回传是否触发运动。
